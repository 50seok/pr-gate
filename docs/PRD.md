## 4. PR 리뷰봇 — `pr-gate` (개인용 축소판, 벤더 중립 · 구독 기반)

### 문제
혼자 만드는 레포에는 리뷰어가 없다. 하자체크에선 PR머신이 그 역할을 했다.
그런데 그 구조(Claude API 직접 호출)를 그대로 개인 레포에 옮기면 **비용과 위험이 과하다** — 자동 머지는 되돌리기 어렵고, PR-M(3번)과 달리 이건 남이 쓰는 서비스가 아니라 **본인 레포만 리뷰**하면 되므로 API 종량제로 돌릴 이유가 없다. **이미 내고 있는 구독(Claude Pro/Max든 다른 AI 에이전트 도구 구독이든)의 포함 사용량**으로 돌린다 — 추가 API 요금 0원이 목표.
추가로: **특정 벤더에 묶이면 안 된다.** 지금은 Claude 구독이 있어서 그걸 쓰지만, 나중에 Codex·Grok·GLM 등 다른 AI 에이전트 도구로 바꾸거나 병행하고 싶을 수 있다 — 리뷰 로직 자체가 "이번에 어떤 도구를 실행하는지"와 무관하게 동작해야 한다.

### 참고 원본 (하자체크 PR머신)
- 별도 레포의 봇이 PR 이벤트 → Claude API 검수 → **자동 머지**(dev 대상)
- 변경 규모로 **티어 분류 → 티어별 모델 배정**(Trivial/Normal=sonnet, Critical=opus) ← 비용 통제의 핵심
- 리뷰 출력 = **P1~P3 등급 + `파일:라인` + 근거 + 수정안**
- 등급이 라벨로: `ai:p1-blocked`(머지 차단), `ai:p2-followup`(후속 이슈 자동 생성)
- `ai:p2-followup` → GitHub Actions가 Jira 태스크 자동 생성. 멱등성 마커 + concurrency로 중복 차단
- ⚠ 원본은 **API 키 기반**(회사 예산). 개인용은 아래처럼 실행 엔진 자체를 바꾼다.

### 축소판에서 뺄 것과 남길 것

| 원본 | 개인용 | 이유 |
|---|---|---|
| **자동 머지** | ✅ **남긴다 — 단 GitHub 네이티브 기능으로** | 봇이 머지 API를 부르지 않는다. 봇은 check를 통과/실패시키고, 머지는 GitHub auto-merge가 한다. 결과는 같은데 봇 코드는 0줄이고 머지 권한도 안 준다 |
| 머지 대상 | `dev`만 | `main` 자동 머지는 배포 훅을 건드린다. dev→main 승격은 사람 |
| **티어별 모델 배정** | ✅ 남긴다 | 설계의 심장. 비용을 규모에 비례시킨다 |
| **P1~P3 + 라벨** | ✅ 남긴다 | 위험도 자동 분류가 본질 |
| **P2 → 후속 이슈 자동 생성** | ✅ 남긴다 | 멱등성 마커 패턴 그대로 |
| Jira 연동 | ❌ 뺀다 | 개인은 GitHub 이슈로 충분 |
| 별도 봇 레포 | ❌ 뺀다 | 워크플로우 1개 + 스크립트 1개로 끝 |
| Claude API 키 | ❌ 뺀다 | 구독 토큰으로 대체 (아래) |

### 인증 — API 키를 쓰지 않는다

`claude setup-token`으로 장기 토큰 발급 → 레포 시크릿 → Actions에서 CLI 실행. 종량 과금 0원.

- **한계**: 주간 사용량 한도를 본인 Claude Code 세션과 **공유한다.** docs-only 스킵 규칙이 비용 절감이 아니라 **한도 절약**을 위해 더 중요해진다.
- **한계**: fork PR은 시크릿이 안 넘어가 검수가 안 돈다. 개인 레포라 무관.
- Actions 연동 세부(액션 입력 이름 등)는 착수 시점에 확인 — 확인된 건 CLI에 `setup-token` 명령이 존재한다는 것까지.

### 에이전트 무관 — 리뷰 실행을 CLI로 추상화

모델 SDK를 봇 코드에 박지 않는다. 리뷰 1회 = 프롬프트 파일 stdin → JSON stdout.

```bash
REVIEW_CMD_SMALL="claude -p --model haiku"
REVIEW_CMD_BIG="claude -p --model sonnet"
$REVIEW_CMD_SMALL < prompt.txt > review.json
```

codex·grok CLI가 생기면 환경변수만 바꾼다. (현재 이 머신엔 `claude`만 설치돼 있어 실검증은 claude로만 가능.)

### 범위 (In)
- `pull_request`(base=`dev`) → diff 수집 → 티어 판정 → `$REVIEW_CMD` 실행 → PR 코멘트 1개 + 라벨
- **티어 규칙** (경로 + 변경 라인 수):
  - `docs/**`, `*.md`만 → **리뷰 스킵** (한도 소모 0)
  - 변경 100줄 미만 → `REVIEW_CMD_SMALL`
  - 100줄 이상 또는 인증/시크릿/DB 관련 경로 → `REVIEW_CMD_BIG`
- **자동 머지**: P1=0 → check 통과 → GitHub auto-merge가 dev에 머지 / P1≥1 → job 실패 → 머지 차단 + `ai:p1-blocked`
- **멱등성**: 코멘트 본문 마커 `<!-- pr-gate:{head_sha} -->`. 같은 커밋 재실행 시 코멘트 갱신(중복 생성 안 함)
- **비용 상한**: diff 8만자 초과 시 파일 목록 + "PR을 쪼개세요"만 남기고 종료
- **사전 설정 1회**: 레포 `Allow auto-merge` 켜기 + `dev` 브랜치 보호에 이 check를 required로 등록

### 범위 밖 (Out)
- `main` 자동 머지 — 사람이 승격한다
- 인라인 코멘트(파일 라인에 직접) — 요약 코멘트 1개가 더 읽기 쉽고 API도 단순
- 자동 픽스/자동 커밋, 대화형 재리뷰(`@bot 다시 봐줘`)

### 핵심 결정
- **워크플로우 1개 + `scripts/review.py` 1개.** 별도 서비스·서버 없음
- **머지는 GitHub이 한다.** 봇은 판정만. 봇에 write 권한을 최소로 유지
- **적용 대상**: 1·2·3번 레포에 붙인다. 봇이 실제로 돌아간 PR 목록이 곧 포트폴리오 증거

### 성공 기준
- [ ] PR을 열면 2분 안에 P등급이 달린 리뷰 코멘트가 붙는다
- [ ] 문서만 고친 PR은 리뷰가 안 돌고 한도도 안 쓴다
- [ ] **P1 없는 PR은 사람 손 없이 dev에 머지된다**
- [ ] P1이 나오면 머지가 막히고 `ai:p1-blocked`가 붙는다
- [ ] 같은 PR에 커밋을 더 올려도 코멘트가 쌓이지 않고 갱신된다
- [ ] P2가 나온 PR에서 후속 이슈가 **정확히 1개** 생성된다 (재실행해도 1개)
- [ ] **API 키 없이 동작한다**

### 리스크
| 리스크 | 대응 |
|---|---|
| 자동 머지가 나쁜 코드를 dev에 넣음 | dev는 배포되지 않는다. `git revert` 가능. main 승격은 사람 |
| 리뷰가 P1을 놓쳐 전부 통과시킴 | **초기엔 auto-merge를 끄고 라벨만 관찰.** 등급이 믿을 만해지면 켠다 |
| 리뷰 품질이 낮아 P등급이 의미 없어짐 | 등급 기준을 프롬프트에 **예시와 함께** 못박는다. P1=동작 안 함/보안, P2=버그 가능성, P3=스타일 |
| 큰 PR 하나로 주간 한도 소진 | diff 크기 컷을 **먼저** 구현하고 리뷰 호출을 나중에 붙인다 |
| 라벨/이슈 중복 생성 | 하자체크가 실제로 겪은 문제(라벨 충돌). 멱등성 마커를 처음부터 넣는다 |
